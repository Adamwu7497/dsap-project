# 台北市救護車派遣模擬與分析

## Proposal Report

### 動機與目標

當意外發生時，及時將病患送往醫院往往是很重要的。

因此，我想透過分析2022~23的救護車派遣事件，

撰寫程式模擬台北市個區域的派遣事件，並分析台北市救護車的分布狀況提出建議。

我想要將結果分成兩者。一個是在事件發生後最佳救援時間內沒有任何救護站能派車抵達便將這個區域記錄下來，一個是在事件發生後最近的救護車站沒有車導致超出最佳救援時間變將這個救護車站記錄下來。目前最佳救援時間設定在30分鐘以下。

### 競品比較

台北市消防局 119 電腦輔助派遣系統：目前 119 勤務中心真正在用的即時派車系統。

他們的產品可以即時模擬案件發生與救護車派遣，但是我的系統才能實際透過明確的目標分類，產出對於目前救護車分布現況的分析。他們的產品仰賴人腦觀察來發現現在救護車分配的問題。

### 預期功能

1.利用python將資料清洗成程式碼易讀的csv檔。

2.利用C++建立模擬系統，動態模擬派遣案件並回傳抵達時間。

3.分析回傳資料尋找台北市內需求量較大的區域。

4.透過最終標記的區域和救護車站分析台北市的救護車分布現況。

### 使用技術

C++：使用為核心模擬系統撰寫的語言。

Python：使用為資料處理、資料分析的工具，並使用其進行結果視覺化。

### Prototype 預計可驗證內容

第一週：清洗資料，輸出成格式統一的csv。

第二週：建立Station、ambulance、case等class和函式，存入各.h檔。

第四週：幫每個station撰寫車輛管理系統。

第五週：寫出main迴圈。

第六週：debug和使用真實資料跑。

第七週：將結果視覺化，生出結論。

第八週：撰寫報告。

### 與課程的關聯

### 使用方式
1. 請確認專案根目錄下包含 clean_data 資料夾，且內部已放置清洗完畢的 csv 檔案。

### 至少提出系統內一個功能流程是使用不同資料結構或演算法來進行實際效能分析跟比較

在這個專案中，對於救護車的排程我使用了紅黑樹，我們使用vector和這個資料結構進行比較。

|  | std::vector | 紅黑樹（std::set） |
| :--- | :--- | :--- |
| **資料結構** | 連續記憶體陣列 | 自我平衡二元搜尋樹 (Self-balancing BST) |
| **插入新歸隊車輛** | 需將資料放至陣列尾端，並呼叫 `std::sort` 重新排序。 | 順著樹狀結構比對大小，自動安插至正確節點並旋轉平衡。 |
| **時間複雜度 (插入)** | $O(N \log N)$ | $O(\log N)$ |
| **取得最快可用車** | 取出陣列第一筆資料，後續元素需全數往前平移。 | 直接回傳樹的最左下角節點 (Root 的極左子節點)。 |
| **時間複雜度 (取出)** | $O(N)$ | $O(1)$ 或 $O(\log N)$ (視實作萃取方式) |
| **實際效能差異分析** | 面對 25 萬筆報案，每台車不斷出勤與歸隊。若使用 Vector，每次歸隊都要重新排序數十台車，造成嚴重的運算瓶頸。 | 透過紅黑樹特性，插入與取出皆被嚴格限制在對數時間內，使系統能在數秒內跑完 25 萬筆事件的動態推演，達成效能碾壓。 |
